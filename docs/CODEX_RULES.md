# Codex Rules for Avantime

1. Общение с пользователем и отчёты ведутся на русском языке.
2. Код, имена файлов, функций, переменных, классов, API и технических сущностей пишутся на английском языке.
3. Комментарии в коде пишутся на английском языке, только если они действительно нужны.
4. Перед любыми изменениями необходимо сначала проанализировать задачу и существующую архитектуру.
5. Нельзя менять архитектуру проекта без явного согласования с пользователем.
6. Нельзя удалять существующую функциональность без прямого разрешения пользователя.
7. Нельзя выполнять Git commit и push без отдельного подтверждения пользователя.
8. После каждой выполненной задачи необходимо:
   - перечислить изменённые файлы;
   - кратко объяснить внесённые изменения;
   - сообщить о результатах проверок;
   - указать найденные ошибки;
   - предложить текст Git-коммита.
9. Перед завершением задачи необходимо запускать доступные проверки:
   - lint;
   - type check;
   - build;
   - tests, если они есть.
10. Если ошибка не связана с текущими изменениями, это необходимо явно указать.
11. Все изменения необходимо выполнять небольшими логическими этапами.
12. Нельзя добавлять новые зависимости без необходимости и объяснения.
13. Нельзя помещать секреты, пароли, токены и API-ключи в репозиторий.
14. Нельзя изменять файлы `.env` и настройки развёртывания без разрешения пользователя.
15. Необходимо сохранять совместимость с существующими страницами, API, личным кабинетом и интеграциями.
16. Для проекта Avantime необходимо учитывать следующие приоритеты:
    - внедрение и сопровождение 1С — основное направление;
    - искусственный интеллект;
    - облачные решения;
    - интеграции;
    - электронный документооборот;
    - Agent+;
    - личный кабинет клиента;
    - база знаний;
    - интеграция с Jira;
    - новости, статьи и вебинары.
17. Перед началом новой задачи необходимо читать этот файл и учитывать его правила.
